# 피키픽 검색 노출 점검 · 개선 기록 (2026-10-30)

기술 SEO, 구조화 데이터, 성능(Core Web Vitals), 콘텐츠·키워드, 네이버·다음·로컬·측정, AI 검색·해외, 6개 분야를 점검했다.
라이브 사이트(picky-pic.com)와 코드를 대조했고, 코드로 고칠 수 있는 것은 이 브랜치에서 고쳤다.
이 문서에는 **코드 밖에서 사장님이 직접 하셔야 할 일**과 **앞으로의 계획**을 남긴다.

**구글**: 이 환경에서는 검색 결과를 직접 볼 수 없었다. Search Console에서 확인해야 한다(아래 3장).

**발견된 핵심 문제** (모두 코드로 수정함)

- **같은 페이지가 두 주소로 색인됨**: `/rental`과 `/rental/`이 네이버에 따로 색인됐다. 블로그는 두 주소가 서로 다른 canonical을 선언하고 있었다.
- **robots.txt가 의도와 반대로 동작**: 봇별 그룹 때문에 Googlebot·Yeti·bingbot에게 `/admin`·`/api`·`/shop` 차단이 적용되지 않았다. `/shop`은 네이버에 색인돼 있었다.
- **사이트맵 누락**: 최신 사례가 담긴 Sanity 포트폴리오 64건이 어떤 사이트맵에도 없었다. 블로그는 메뉴·푸터 어디에도 연결되지 않았다.
- **SEO 랜딩 페이지가 고아 페이지**: 렌탈·창업·팝업·기업행사·레트로 페이지가 본문 링크 없이 10px 푸터 링크로만 연결돼 있었다. "포토부스 렌탈", "기업행사 포토부스"가 1페이지에 없는 주원인으로 본다.
- **관리자 SEO 설정 미반영**: 관리자에서 입력한 블로그 검색용 제목·설명이 실제 페이지에 반영되지 않았다.
- **소프트 404**: 없는 글·사례 주소가 목록으로 302 이동했다. `/api/*`에 GET 요청을 보내면 500 오류가 났다.
- **구조화 데이터 결함**:
  - 모든 페이지의 breadcrumb URL이 `//about` 형태로 깨져 있었다.
  - 제품 9종 Product 마크업이 무효였다(가격 없는 Offer).
  - 로고가 Google 최소 크기(112px) 미만이었다.
  - 전화번호 형식이 틀렸고, 좌표는 성수역(약 450m 차이), 우편번호는 04790(실제 04787)이었다.
- **정보 오류**:
  - 푸터·구조화 데이터의 카카오 채널(`_pickypic`)이 존재하지 않는 채널이었다.
  - 해외에서는 전화 링크로 걸 수 없었다.
  - 끝난 Kickstarter를 "9월 22일 출시 예정"으로 안내하고 있었다.
- **속도 문제**:
  - 포트폴리오가 Sanity 원본 이미지를 그대로 써서 페이지당 7MB 이상, LCP 27초였다.
  - `/rental`은 LCP가 아예 기록되지 않았다.
  - 홈은 모바일에서 데스크톱 이미지까지 받았고, 팝업 때문에 CLS가 0.22였다.

## 2. 이번에 고친 것 (요약)

- **URL**:
  - canonical·사이트맵·hreflang·내부 링크를 "끝 슬래시 없음"으로 통일했다(루트 `/` 제외). 슬래시 붙은 주소는 301로 이동한다.
  - 구 그누보드 `/bbs` 주소를 새 페이지에 1:1로 연결했다.
  - `pickypic.co.kr`, `*.vercel.app`은 301로 넘긴다.
- **색인 신호**:
  - robots.txt를 한 그룹으로 정리했다.
  - 사이트맵 인덱스에 블로그·포트폴리오·이미지 사이트맵을 모두 넣었다.
  - 의미 없던 lastmod를 지웠다.
  - `/shop`·404는 noindex로 바꿨다.
  - 메타 keywords와 봇별 메타를 지웠다.
- **404**: 없는 글·사례는 진짜 404로 응답한다. API에 지원하지 않는 메서드로 요청하면 405를 돌려준다.
- **구조화 데이터**:
  - 회사·사이트·페이지를 `@id`로 잇는 그래프로 정리했다(`src/data/structuredData.ts`).
  - breadcrumb, 로고, 전화번호, 좌표, 우편번호를 고쳤다.
  - 제품 마크업은 라인업 목록으로 바꿨다.
- **콘텐츠**:
  - 홈은 키워드가 든 H1 하나, 읽을 수 있는 소개문, 랜딩 페이지 링크 7개로 바꿨다.
  - 렌탈·제품·포트폴리오·회사소개·사례 상세에 H1을 넣었다.
  - 페이지별 제목·설명을 다듬었다. 서로 잠식하던 키워드를 나누고, "가격 안내", "인생네컷" 같은 문구를 정리했다.
  - FAQ 키워드 제목이 덮이던 문제를 고쳤다.
  - 블로그·포트폴리오에 관리자 SEO 필드를 반영했다.
  - 블로그를 푸터에 연결했다.
  - llms.txt를 다시 썼다.
- **속도**:
  - Sanity 이미지를 크기에 맞게 받는다.
  - 홈 히어로와 제품 이미지는 표시 크기에 맞는 사본을 만들어 쓴다.
  - `/rental`·`/en` 캐러셀의 LCP 버그를 고쳤다.
  - 글꼴 CSS를 4분의 1로 줄였다.
  - 효과 없던 폰트 숨김과 1초마다 돌던 채널톡 제거 스크립트를 뺐다.
  - 블로그·사례 페이지를 엣지 캐시한다.
- **측정**: 문의 성공·실패(`generate_lead`, `form_error`)와 전화·카카오·이메일·스마트스토어 클릭(`contact_click`)을 dataLayer 이벤트로 보낸다.
- **보안·관리자**:
  - 색인 요청 API에 관리자 인증을 걸었다.
  - Google Indexing API는 발행 흐름에서 뺐다(Google 정책상 채용공고·라이브 방송 전용).
  - 에디터가 저장된 슬러그의 canonical URL로 색인을 요청한다.
  - 포트폴리오 제목을 바꿔도 URL은 유지된다.

- **사이트 블로그와 네이버 블로그의 역할을 나눈다.**

### 기술 (다음 단계 후보)

- **한국어 문구 통일**: 클라이언트 번역(ko)이 서버 HTML과 다른 곳이 약 15군데 남아 있다. 정본을 정해 맞춘 뒤, 번역 사전을 언어별로 나눠 필요할 때만 불러온다(페이지당 약 40KB 절감).
- **애니메이션 경량화**: GSAP를 CSS 전환 + IntersectionObserver로 바꾼다(약 45KB 절감, 강제 레이아웃 제거).
- **나머지 이미지 최적화**: 포트폴리오 로컬 썸네일 79장을 표시 크기 사본으로 바꾼다.
- **제품 리치 결과**: 모델별 개별 페이지를 만든다. 가격을 공개해야 Google 제품 리치 결과 대상이 된다.
- **해외 페이지**: `/en/photo-booth-rental-korea`(서울 팝업 렌탈 영문 페이지)를 만들고 `/photobooth-rental`과 hreflang으로 짝짓는다. `/en/kickstarter`는 상시 페이지 `/en/receipt-photobooth`로 바꾸는 것을 검토한다.
- **홈 팝업**: 모바일 첫 화면의 약 75%를 가린다(Google의 방해형 전면 광고 기준). 지연 표시나 하단 배너 형태로 바꾸는 것을 검토한다.
- **글꼴 자체 호스팅**: Noto Sans KR을 자체 호스팅해 외부 연결 2개를 줄인다.

## 5. 배포 직후 확인

```bash
curl -sI https://picky-pic.com/rental/            # 301 → /rental
curl -sI https://picky-pic.com/en/                # 301 → /en
curl -sI https://picky-pic.com/api/sanity         # 405 (예전 500)
curl -sI https://picky-pic.com/blog/없는-주소      # 404
curl -sI "https://picky-pic.com/bbs/board.php?bo_table=portfolio&wr_id=10"   # 301 → /portfolio/10
curl -sI https://pickypic.co.kr/                  # 301 → https://picky-pic.com/
curl -s  https://picky-pic.com/sitemap-index.xml  # 사이트맵 4개
curl -sI https://picky-pic.com/admin | grep -i x-robots-tag
```

- 렌탈·협업·영문 문의 폼을 하나씩 실제로 제출해 정상 접수되는지 확인한다.
- GTM 미리보기에서 `generate_lead`가 발생하는지 확인한다.
- 관리자에서 블로그 글을 저장했을 때 색인 요청이 200/202로 응답하는지 확인한다(브라우저 콘솔 `[indexing]`).
